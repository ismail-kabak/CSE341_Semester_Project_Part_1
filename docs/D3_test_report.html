Program 1 — Parameterized recipe with helper function and scaling (sample1.rcx)

Exercises: function declaration, recipe declaration, ingredient expressions using function calls, repeat loop, step modifiers (at/for), evaluate + scale.

// Sample 1 — A recipe using a helper function

function half(n: int) -> int {
    return n / 2
}

recipe pancakes(servings: int) serves servings {
    ingredient flour : 50 g * servings
    ingredient milk  : 60 ml * servings
    ingredient eggs  : half(servings) * 1 count
    ingredient salt  : 1 pinch

    step "Mix dry" {
        combine(flour, salt)
    }
    step "Add wet" {
        combine(milk, eggs)
    }
    step "Cook batches" at 180 °C for 3 min {
        repeat servings times {
            pour(milk)
            flip()
        }
    }
}

evaluate scale(pancakes(servings: 4), by: 1.5)
OK — parsed tests/fixtures/valid/sample1.rcx

Features demonstrated:

  • function half(n: int) -> int — scalar helper with parameter and return
  • half(servings) * 1 count — constructing a Count quantity from a computed value (Decision #30)
  • 1 pinch — ceremonial Pinch type (Decision #4)
  • combine(flour, salt) — action verb mixing Mass and Pinch (Decision #29 exception)
  • at 180 °C for 3 min — both step modifiers present; fixed order enforced (Decision #23)
  • scale(pancakes(servings: 4), by: 1.5) — keyword-arg recipe call inside scale (Decision #25)

Invalid 1 — Missing braces on if body

Decision #20: Both if and else branches require mandatory braces. Eliminates dangling-else ambiguity (Sebesta §3.4).

// INVALID: missing braces on if body (Decision #20)

function check(n: int) -> bool {
    if n > 0
        return true
    return false
}

evaluate check(1)
parse error at line 6, col 0: expected '{' after 'if' condition (braces are mandatory), got 'return' ('return')

Why this is a parse error: The grammar requires "{" stmts "}" immediately after the if condition. The parser found return where it expected {.

Invalid 2 — Wrong step modifier order (for before at)

Decision #23: The at modifier must appear before the for modifier. Both are optional but the order is fixed.

// INVALID: step modifier 'for' before 'at' (Decision #23)

recipe cake() serves 1 {
    ingredient flour : 200 g

    step "Bake" for 30 min at 180 °C {
        bake(flour)
    }
}

evaluate cake()
parse error at line 7, col 0: 'at' modifier must come before 'for' modifier in step declaration (Decision #23)

Why this is a parse error: The grammar production for step is "step" STRING [ "at" expr ] [ "for" expr ]. After consuming the for modifier and its expression 30 min, the parser finds at where it expects {, revealing the reversed order.

Invalid 3 — Expression in substitute ingredient slot

Decision #35: The two ingredient-name slots in substitute() must be bare identifiers (IDENT terminals), not general expressions.

// INVALID: expression in substitute's ingredient slot (Decision #35)

recipe smoothie(servings: int) serves servings {
    ingredient milk     : 150 ml * servings
    ingredient oat_milk : 150 ml * servings

    step "Blend" {
        blend()
    }
}

evaluate substitute(smoothie(servings: 2), milk + oat_milk, with: oat_milk, ratio: 1.0)
parse error at line 13, col 0: substitute: original ingredient must be a bare identifier — expressions are not allowed here (Decision #35 / error #17); got 'PLUS' after identifier 'milk'

Why this is a parse error: After consuming the IDENT milk, the parser checks that the next token is ,. It finds + instead, indicating an expression where only an identifier is allowed. The grammar uses IDENT (not <expr>) as a terminal in the substitute production.

Invalid 4 — Chained comparison (a < b < c)

Decision #17: Comparison operators are non-associative. Chaining like a < b < c is a parse error.

// INVALID: chained comparison a < b < c (Decision #17)

function between(x: int) -> bool {
    return 0 < x < 10
}

evaluate between(5)
parse error at line 5, col 0: comparison operators are non-associative; use parentheses to group comparisons (Decision #17)

Why this is a parse error: The grammar production for relational expressions uses [ op expr ] (optional, once) rather than { op expr } (repeating). After parsing 0 < x, the parser sees another < and raises a non-associativity error rather than silently producing (0 < x) < 10 — which would be a bool-to-int coercion trap.

Invalid 5 — quantity_of without parentheses

Decision #34: quantity_of is a unary operator that requires parentheses: quantity_of(expr). It cannot be used without them.

// INVALID: quantity_of used without parentheses

recipe bread() serves 1 {
    ingredient flour : 200 g

    step "Mix" {
        let q : Mass = quantity_of flour
    }
}

evaluate bread()
parse error at line 8, col 0: expected '(' after 'quantity_of', got 'IDENT' ('flour')

Why this is a parse error: The grammar production for quantity_of is "quantity_of" "(" <expr> ")". The parser consumed the quantity_of keyword and expected (, but found the identifier flour directly. This enforces Decision #34 — quantity_of is a dedicated unary operator with mandatory parentheses, not a keyword that can modify any following expression.
