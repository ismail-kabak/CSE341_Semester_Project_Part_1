## Phase 0 — Contracts (tonight, joint, ~3 hours, before anyone writes code)

This is the equivalent of `tokens.py` for Part 2. Both of you sit down together (call or in-person, not async) and nail these decisions in a single short markdown doc — `recipix_v4_1_runtime_contract.md` — committed to the repo before either of you opens an editor.

**1. TypedAST contract.** In-place annotation: the type checker adds `.inferred_type` to every `Expr` node and `.resolved_kind` to every `AmbiguousCall` (values `"recipe"` or `"function"`). Statement nodes get nothing — they have no type. The interpreter ignores `.inferred_type` except where it needs runtime dispatch (which, for Recipix, is essentially never — the parser already discriminates by node class). This means **the interpreter can be written and tested against the un-annotated AST in parallel with the type checker** — you don't block on İsmail.

**2. Runtime value representations.** Decide the Python representation of each Recipix value:
- `RtQuantity(value: float, dimension: str)` — value is always in the dimension's base unit (`g`, `ml`, `count`, `°C`, `min`). Dimension is `"Mass" | "Volume" | "Count" | "Temperature" | "Duration"`.
- `RtPinch` — a singleton; ceremonial, no fields.
- `RtIngredient(name: str, quantity: RtQuantity | RtPinch)`.
- `RtRecipe(name: str, servings: int, ingredients: dict[str, RtIngredient], steps: list[StepDecl])` — steps are stored as AST nodes; rendering walks them.
- `RtList(elements: list, element_type: str)`.
- `int / float / bool` use Python natives.

**3. Action-verb signature table.** Lock it in the contract doc, 12 rows. My straw proposal — adjust together:
- `combine`, `mix`: ≥2 args, any Ingredient or Quantity, heterogeneous OK.
- `pour`, `drizzle`: 1 arg, Volume-bearing Ingredient or Volume Quantity.
- `add`, `sprinkle`: 1 arg, any Ingredient (incl. Pinch).
- `whisk`, `blend`, `knead`, `melt`: ≥1 arg, any Ingredient or Quantity.
- `bake`: zero args (modifiers `at` and `for` carry the parameters).

**4. Quantity normalization rule.** Type checker tracks dimension abstractly (it doesn't need the numeric value). Interpreter normalizes to base unit at `QuantityLit` evaluation.
